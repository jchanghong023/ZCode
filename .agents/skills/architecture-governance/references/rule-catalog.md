# Rule catalog

| Rule                         | Meaning                                                                                          | Typical fix                                                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `module-dependency`          | Cross-module import is missing from `requires`                                                   | Add a public contract or move the integration owner                                                                                                          |
| `deep-import`                | Import bypasses a module public entrypoint                                                       | Import the contract/index entrypoint                                                                                                                         |
| `cycle`                      | The managed dependency graph contains a cycle                                                    | Split the owner or invert the dependency through a port                                                                                                      |
| `max-file-lines`             | Managed source exceeds the policy budget                                                         | Split by responsibility; do not add a disable                                                                                                                |
| `max-contract-lines`         | A contract is too broad                                                                          | Split the capability or reduce the public surface                                                                                                            |
| `max-public-methods`         | A contract exposes too many methods                                                              | Split the capability or introduce a narrower read/write contract                                                                                             |
| `layer-direction`            | A layer imports a higher implementation layer                                                    | Depend on a lower layer port or move the integration owner                                                                                                   |
| `domain-io`                  | Domain code imports process, network, filesystem, or timer APIs                                  | Move IO to an adapter and pass a typed port into the domain                                                                                                  |
| `ui-implementation-import`   | A file in a `ui` layer imports a repository, runtime, or service implementation                  | Depend on the module port / read model exposed by `contract.ts`                                                                                              |
| `missing-module-artifact`    | A managed module lacks its manifest or contract fixtures                                         | Add the required module contract, example, and CONTRACT.md                                                                                                   |
| `disable-count`              | Managed code adds a lint suppression                                                             | Fix the underlying violation or add a reviewed expiring exception                                                                                            |
| `unmanaged-new-file`         | A newly added source file under `packages/` or `apps/` is not inside a managed module            | Put it in a managed module, or run `bun run architecture:adopt <id> --root <dir>` to register its directory (tests, `.d.ts` and test directories are exempt) |
| `manifest-policy-mismatch`   | `module.ts` `requires` disagrees with `architecture-policy.yaml` or names an unknown module      | Update both declarations in the same change; the policy owns topology, the manifest owns the local declaration                                               |
| `missing-policy-path`        | A root, public entrypoint, or exception path no longer exists (glob exceptions must match files) | Remove retired registrations and dependencies, or correct the live path                                                                                      |
| `missing-package-entrypoint` | A workspace exports/imports target has no file or supported TypeScript output                    | Correct the declaration; never restore retired modules to satisfy it                                                                                         |
| `browser-policy`             | A browser scope/package or Node-only entrypoint is invalid                                       | Correct the executable boundary registration                                                                                                                 |
| `browser-node-import`        | Browser runtime dependencies reach a Node builtin, native package, or Node-only entrypoint       | Keep IO in the Node owner and expose a browser-safe contract                                                                                                 |
| `browser-node-contract`      | A browser type dependency reaches a Node-only implementation                                     | Extract shared DTO/schema instead of relying on type erasure                                                                                                 |
| `browser-node-entrypoint`    | Browser code reaches a Node-only entrypoint through a file path                                  | Use a browser-safe public surface                                                                                                                            |

Existing legacy violations are suppressible through `.architecture-baseline.json`. Policy/package integrity and browser-boundary rules always block, even under `--changed`; baseline updates never accept them.

Import edges are resolved the way Node and TypeScript resolve them: relative paths, `package.json` `imports` (`#src/*`), `tsconfig.json` `paths` (`@/*`), and workspace package names with `exports` (conditional exports and `dist/` targets map back to `src/`). `--changed` compares against a real base (explicit `--base`, CI merge-request variables, optional pre-push input, upstream, then the default branch merge-base), rather than inspecting only dirty files. This describes the checker’s supported inputs; the repository does not install a pre-push hook.

Browser boundaries use `global.browserScopes`, all exports of `global.browserPackages`, explicit `global.nodeEntrypoints`, and forbidden `global.nativePackages`. Runtime traversal includes literal dynamic imports and require calls, uses browser/import/default conditions, and follows safe type contracts without treating type-only Node builtin declarations as runtime IO.
