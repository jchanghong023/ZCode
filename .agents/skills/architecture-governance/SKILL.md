# AIReq 架构审查

页面文案、样式及模块内逻辑按对应功能规格修改。变更跨越模块边界时，使用下表定位契约。

| 变更           | 检查重点                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| UI 调用服务    | 页面通过 hook 和服务契约读取投影、提交意图；平台能力由 Web 入口注入。                                                   |
| 共享类型或 RPC | 从包的公开入口导入。接口、descriptor、校验、服务实现和调用方同步更新。浏览器依赖图只使用浏览器安全入口。                |
| 状态或事件     | 明确唯一写入方。业务材料与审批归 workflow，会话、队列与订阅归原生会话服务。先校验再提交，最后通知；重连恢复订阅并重读。 |
| 新增模块依赖   | 查看双方的公开入口及允许依赖。需要明确独立职责时登记受管模块。                                                          |

在仓库根运行 `bun run architecture:context <module-id>` 定位受影响的契约，例如 `aireq-ui`。规则与检查范围见[模块说明](../../../docs/architecture/pure-web-module-ownership.md)。

运行 `bun run architecture:check --changed` 检查改动，修改策略或检查器后再运行全量 `bun run architecture:check`。业务行为按影响选择前端 UT、后端 ST 或桌面浏览器验证。
