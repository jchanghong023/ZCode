# 需求与研发列表留白打磨

2026-11-17，用户授权 Impeccable polish：以外观页的正文比例为基准，减少常驻说明、增加留白，正文随可用区域收窄且居中。此文仅定义需求共创、开发任务与进度分析的局部呈现；共享容器／标题由 pageLayout 及设置页规格统一维护，项目／具体 Release、业务操作与状态 owner 不变。

- 开发任务用当前 IR 的简短业务标题作为主行，原始短需求继续保留在该标题的完整提示与对象详情；编号、完成 SR 数不删。正常报告不逐行重复“无阻断问题”，未分析／失败／过期／测试问题／分支异常仍常驻并可查看完整详情。表格行内边距增加，负责人及排期事实不删。
- 需求共创原始需求在列表最多显示三行，完整原文仍是同一个按钮的可访问文本，悬停／键盘聚焦提示完整内容，点击仍进入同一提案讨论。提交时间以短格式展示，完整北京时间保留于 time 标题与 dateTime；时区在表头统一说明，不逐行重复。
- 分析页保留自动分析状态；下次检查时间与项目运行数放入具名“调度详情”弹层，保留键盘入口，减少常驻状态行长度。任务、历史、手动分析与分析设置不变。表格行增加纵向留白。
- 一级列表标题不额外增加顶部 padding；正常空态、失败、历史、完整材料和确认门禁不因文案精简而隐藏。电脑浏览器深浅主题验收，包含父级正文收窄和右侧栏展开；不做手机适配。

验收：IR 标题能打开原对象且完整原文可读；提案原文三行且完整提示、日期可追溯；警告／失败仍常驻；分析调度详情展示同一快照时间及运行数；表格筛选、展开、报告和业务操作无回归。所有新增展示状态仅由现有 Popover 持有，不建立第二份业务缓存。

收口复核：提案表在限宽正文下为提交人、短日期、状态和操作采用固定可读列宽，原文使用剩余空间；表格最小宽度沿用3xl尺度，窄面板仅局部横滚，避免状态字段被百分比分配挤成三四行。
