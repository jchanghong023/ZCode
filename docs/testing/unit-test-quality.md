# 前端 UT 与后端 ST

| 自动化测试 | 范围                                                                 | 运行              | 检查用例类型                |
| ---------- | -------------------------------------------------------------------- | ----------------- | --------------------------- |
| 前端 UT    | `test/ut/`，独立验证 Web 前端函数与状态逻辑                          | `bun run test:ut` | `bun run test:ut:typecheck` |
| 后端 ST    | `test/st/`，通过 HTTP、WebSocket 和 Channel RPC 验证已启动的后端服务 | `bun run test:st` | `bun run test:st:typecheck` |

前端 UT 从 `test/ut/*.test.ts` 自动发现，后端 ST 从 `test/st/*.test.ts` 独立发现。命令定义见[根工程配置](../../package.json)。

UT 从消费者可观察的行为编写断言，通过可控 Promise 和公开事件安排时序。每例恢复替换的存储、计时器和监听。

## React Hooks 检查

`bun run lint` 使用 Oxlint 检查 Hook 调用顺序和闭包依赖。修改根配置忽略的 `components/ui`、`components/ai-elements` 时，用临时配置显式检查目标文件的 `react/rules-of-hooks` 和 `react/exhaustive-deps`。调整依赖后复核订阅的创建、清理及重读时机。规则见[根配置](../../.oxlintrc.json)。

## HTTP／WebSocket ST

启动服务后执行 `bun run test:st`，默认连接 `http://localhost:5174`。测试走正式 HTTP 和二进制 Channel RPC，以业务规格及公开服务契约为断言依据。单 worker 串行验证业务操作，等待相应的服务端事实后读取结果。

ST 使用专用服务实例；不与手工或浏览器验收共享状态。最近会话按全入口的活动排序，浏览器发消息会改变 ST 的排序前置；AIReq 的普通 CAS 写入也可能与对方的写入冲突。并行验收时，为 ST 设置独立的 `ST_BASE_URL`。

| 需要调整的项目 | 配置                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------- |
| 服务与身份     | `ST_BASE_URL`、`ST_EMPLOYEE_ID`、`ST_OTHER_EMPLOYEE_ID`、`ST_TESTER_EMPLOYEE_ID`、可选 `ST_TOKEN` |
| 专用仓库与分支 | `ST_REPOSITORY_URL`、`ST_REPOSITORY_BRANCH`                                                       |
| 共享文档目录   | `ST_WORK_DIRECTORY_ROOT`：服务端和测试进程都能访问的可读写挂载                                    |
| 等待时限       | `ST_TIMEOUT_MS` 默认 120000                                                                       |
| 文件与前置数据 | `ST_FILE_JSON`、`ST_FIXTURES_FILE`                                                                |
| 隔离红区同步   | `ST_ISOLATED_RED_ZONE_SYNC=1`：仅在整套目录与接收端均专供本轮验收时设置                           |

配置格式与默认值见[测试配置](../../test/st/config.ts)。项目和 IR 由云龙提供，Release 从项目 IR 汇总；AIReq 不提供创建或删除这些对象的界面或公开命令。ST 不通过 AIReq 业务写入、云龙 CLI 或直接写存储来造对象，也不持久化或删除云龙业务 IR。需求共创从环境预备的专用 IR 开始，通过原生对话生成和编辑 AIReq 材料。业务、开发和测试角色使用三个不同的普通工号，由测试环境的管理员分配对应项目权限。评审使用接纳时最新的已保存文件；同版本文件变化后，旧报告应标为过时。

### 前置清单与占用

`ST_FIXTURES_FILE` 指向 JSON 文件，顶层对象按用途映射到对象数组。完整验收每轮按下表准备资源：

| 用途           | 内容与容量                                                                                                                                                                                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requirements` | 每项提供云龙 `projectId`（项目组 ID）和 `irId`（IR 业务号），可选 `releaseId`；需要指定 Release 的场景要预备对应的记录。按数组顺序为变更场景一次性占用，每轮同一 `(projectId, irId)` 只能用于一个变更场景。容量须覆盖本轮所有变更场景，不从任意已有业务 IR 中挑选补位。 |
| `projects`     | 两个专用测试项目组，条目提供 `projectId`。一个在开跑前通过公开项目配置保存仓库地址、分支和共享目录，供 CAS 与软链接测试；另一个保持未配置并标记 `allowUnconfigured: true`，供目录迁移。相关 `requirements` 条目必须属于对应项目；其他专用 IR 可分布在这两个项目中。     |
| `media`        | 沿用现有格式：如提供该数组，首项须有 `path`、`mediaType` 和 `bytesBase64`，对应一个可由服务读取且字节已知的实际媒体文件。                                                                                                                                               |

写入前通过正式 RPC 核验夹具：`readWorkflow` 确认项目和 IR 的归属；提供 `releaseId` 时核对该 Release 属于同一项目，且该 IR 确实在该 Release 下。缺少前置、归属不符、重复或耗尽时报告「ST 前置阻塞」，不临时造数据、不换用任意业务对象。

项目配置已有基线时，测试在原工作目录内临时修改可回写字段。恢复前核对当前 revision 与内容仍是本例写入值，再按 CAS 恢复；冲突时停止恢复并记录，不覆盖其他写入。工作目录迁移不能切回有内容的旧共享目录，因此迁移场景只使用明确可保留终态的专用项目：在 `projects` 条目标记 `allowUnconfigured: true`。全局配置同样仅在版本与内容仍属于本轮修改时恢复。

工作目录发布用例从测试进程访问服务端同一挂载，验证既有软链接可读取新增或更新的最新版材料。原型可用语法有效的保留域名作为 `ST_REPOSITORY_URL`，验证保存只依赖本地配置和共享目录；这不验证正式环境的仓库访问。

### 工作流与新增契约测试

普通命令按工作流 revision 验证 CAS。定版用例提交预检返回的 `snapshot`，验证同版文件变更和后续版本拒绝旧快照、旧工作流 revision 不阻止快照一致的定版，以及成功请求重试返回原回执。快照匹配但复核失败时，验证报告 `documentValidation` 与失败的 `receipt` 同级，材料、版本及工作流 revision 不变。成功后验证全部文件和确认记录；新版本生成后仍读取到上一版的原始内容。

| 契约           | 验证范围                                                                                                                                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 云龙目录与详情 | 项目与 Release 的总数、云龙完成数及 AIReq 当前版本定版数分开统计，项目总数包含未分配 Release 的 IR；详情按项目和业务号返回完整原始描述。普通读取和重连复用页面快照，显式刷新获取新快照，失败保留旧数据，不替换其他页面的快照。已撤下的创建及删除入口应被拒绝且无业务副作用。                                  |
| 列配置         | 公开 RPC 校验列键、唯一性和排序列可见性；默认按创建时间降序的例外可用。首迁不覆盖服务端原值，同工号回读、不同工号隔离。前端 UT 核对精简布局、列筛选与排序分页的关系。配置写入使用专用测试身份。                                                                                                               |
| IR 评论        | 评论列表的顺序、正文和可空 ID；错误归属拒绝，非空和长度约束生效。变更用例只在专用 IR 上添加、回读并删除本例自己的评论，不删除预存评论或 IR。                                                                                                                                                                  |
| 主题           | 前端 UT 验证 AIReq 新页面默认钴蓝日间、当前页面选色即时生效、重连保留且刷新复位；广播不覆盖当前页面的主动选择，不持久化主题。ST 验证公开设置和广播的输入、回执及事件边界。                                                                                                                                    |
| 红区同步       | 从指定 Release 发起，验证交接仍覆盖全部项目和未分配 Release 的 IR，包含完整原始描述和已有的完整需求正文；重复交接保留红区自有文件及快照未附带的文件。核对回执状态与计数，原型只记 `simulated`。全量同步 ST 要求目标服务可见的整个目录和接收端均为隔离测试环境；不对共享真实目录执行，缺任一项即报告前置阻塞。 |

### 原型与正式环境的测试复用

原型阶段把前端 UT 和后端 ST 对齐到已确认的业务要求。验收通过后，用该版测试验证正式对接，测试源码、用例步骤和断言保持一致。切换环境通过上表的配置指定服务地址、测试仓库和前置数据。ST 始终通过同一套公开 HTTP、WebSocket 和 Channel RPC 契约发起操作及核对结果。默认 `bun run dev` 提供的普通云龙样例只有少量 IR，可用于不写需求材料且无需专用 IR 的契约用例；这只验证原型契约，不能代替两轮完整验收，也不能作为真实云龙、红区交接或正式后端验证结果。

需要外部事实的用例由所在环境准备。版本测试在两种环境都校验同一 IR、完整文件、确认人工号和确认时间，并在新版本生成后核对上一版的原始内容。前置条件未满足时按下文报告阻塞。切换规则见[发布边界](../specs/aireq/contract-design.md#发布边界)。

### 完整 ST 验收

对同一服务进程连续执行两次完整的 `bun run test:st`，两轮之间不重启服务。每轮换独立的 `ST_FIXTURES_FILE`、运行标识和占用记录，使用不同的专用 IR 和项目夹具。由测试环境在开跑前备齐两轮所需资源，或在两轮之间由环境补齐并由 ST 通过正式 RPC 核验；测试不负责供应业务对象。

两轮须实际跑完完整套件才算验收完成。任一轮前置不具备，明确记录阻塞；第二轮阻塞时保留首轮实测结果，不把首轮、普通样例或跳过项算成两轮通过。验收记录注明服务及云龙／红区环境、每轮占用、通过、失败、跳过、阻塞和未覆盖项，以及测试拥有的配置恢复或约定终态。模拟后端的结果仅用于该环境的验收。
