# 前端 UT 与后端 ST

| 自动化测试 | 范围                                                                 | 运行              | 检查用例类型                |
| ---------- | -------------------------------------------------------------------- | ----------------- | --------------------------- |
| 前端 UT    | `test/ut/`，独立验证 Web 前端函数与状态逻辑                          | `bun run test:ut` | `bun run test:ut:typecheck` |
| 后端 ST    | `test/st/`，通过 HTTP、WebSocket 和 Channel RPC 验证已启动的后端服务 | `bun run test:st` | `bun run test:st:typecheck` |

前端 UT 从 `test/ut/*.test.ts` 自动发现，后端 ST 从 `test/st/*.test.ts` 独立发现。命令定义见[根工程配置](../../package.json)。

UT 从消费者可观察的行为编写断言，通过可控 Promise 和公开事件安排时序。每例恢复替换的存储、计时器和监听。

## React Hooks 检查

`bun run lint` 使用 Oxlint 检查 Hook 调用顺序和闭包依赖。修改根配置忽略的 `components/ui`、`components/ai-elements` 时，用临时配置显式检查目标文件的 `react/rules-of-hooks` 和 `react/exhaustive-deps`。调整依赖后复核订阅的创建、清理及重读时机。规则见[根配置](../../.oxlintrc.json)。

## HTTP／WebSocket ST

启动服务后执行 `bun run test:st`，默认连接 `http://localhost:5174`。测试走正式 HTTP 和二进制 Channel RPC，以业务规格及公开服务契约为断言依据。单 worker 串行验证业务操作，等待相应的服务端事实后读取结果。

ST 使用专用服务实例；不与手工或浏览器验收共享状态。最近会话按全入口的活动排序，浏览器发消息会改变 ST 的排序前置；AIReq 的业务写入也可能使对方读到的工作流版本失效。并行验收时，为 ST 设置独立的 `ST_BASE_URL`。

| 需要调整的项目 | 配置                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| 服务与身份     | `ST_BASE_URL`、`ST_EMPLOYEE_ID`、`ST_OTHER_EMPLOYEE_ID`、可选 `ST_TOKEN` |
| 专用仓库与分支 | `ST_REPOSITORY_URL`、`ST_REPOSITORY_BRANCH`                              |
| 等待时限       | `ST_TIMEOUT_MS` 默认 120000                                              |
| 文件与前置数据 | `ST_FILE_JSON`、`ST_FIXTURES_FILE`                                       |

配置格式与默认值见[测试配置](../../test/st/config.ts)。归档测试通过公开接口创建独立提案、提交当前候选并读取归档结果。

删除需求仅限本轮通过公开流程创建并登记的 IR。全局配置仅在版本与内容仍属于本轮修改时恢复。

### 原型与正式环境的测试复用

原型阶段把前端 UT 和后端 ST 对齐到已确认的业务要求。验收通过后，用该版测试验证正式对接，测试源码、用例步骤和断言保持一致。切换环境通过上表的配置指定服务地址、测试仓库和前置数据。ST 始终通过同一套公开 HTTP、WebSocket 和 Channel RPC 契约发起操作及核对结果。

需要外部事实的用例由所在环境准备。归档测试在两种环境都校验同一 IR、完整清单和只读视图。前置条件未满足时按下文报告阻塞。切换规则见[发布边界](../specs/aireq/contract-design.md#发布边界)。

### 完整 ST 验收

对同一已运行的服务连续执行两次 `bun run test:st`，使用不同的运行标识。每轮为会改变业务状态的用例分配独立前置对象，并记录分配与消耗情况。首轮前准备两轮所需对象，或在两轮之间通过正式流程补充并核验。两轮之间保持服务运行，通过公开流程准备数据。

两轮都须实际执行完整套件。第二轮缺少前置数据时，记录首轮结果及第二轮阻塞原因。验收记录注明服务环境、通过、失败、跳过、阻塞和未覆盖项，以及新增资源的清理结果。模拟后端的结果仅用于该环境的验收。
