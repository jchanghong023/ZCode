# 测试规格：清空现有用例，保留测试基础设施

更新日期：2026-11-17

## 1. 本轮范围

按用户最新要求，删除仓库现有全部自动化测试用例及其专用夹具，让后续测试从零重新编写。不保留旧工程测试、业务测试、集成测试、E2E 或回归用例，不新增替代测试。

保留项目依赖、锁文件、测试运行器及其补丁、框架配置、初始化、通用测试辅助、包命令和安装流程。不以本次删除为由卸载依赖、拆除测试基础设施、修改生产代码或禁止后续编写测试。

## 2. 用例发现与登记

根工程测试仍沿用 `scripts/engineering-test-files.json` 与现有 Vitest 配置；清空旧文件登记，后续将新用例的精确路径加入清单。

工程门禁测试入口保留，但发现范围不能继续枚举已删除的旧文件。测试为空时如实报告无测试，不新增占位断言、不伪造覆盖率或沿用历史通过。

仅将旧用例／夹具的精确文件路径改为通用发现或清空登记；保留现有类型检查项目、测试运行器依赖及通用配置。新用例需要扩展类型检查接线时随用例实际维护。

## 3. 保留的生产能力与证据

- 产品中的“测试验收”、测试结果与状态、生产 schema、校验、身份隔离、CAS／幂等、错误处理不属于测试用例，不删除。
- 通用 UI 控件、生产交互使用的 DOM 标识、文件类型图标、产品资源及真实示例不删除。
- 已完成的浏览器／协议验收记录与产物指纹保留历史版本和时间，不冒充当前源码覆盖。
- 类型、Lint、格式与架构静态检查保留。删除检查工具自身的测试，不删除实际检查工具。

## 4. 后续重新编写

新增测试仍以真实消费者可观察的行为、失败路径和副作用为对象，复用保留的框架、配置和项目依赖；不恢复旧用例作为占位，也不把“没有测试”说成验证通过。

本轮只核验旧测试与专用夹具已经清空、项目依赖和锁文件未改变、没有对已删文件的失效执行引用，以及必要非测试工程检查结果；不运行已经删除的用例或另建测试。

## 5. 本轮清空结果

- 删除全部 25 个旧测试文件及 6 个用例专用夹具；仓库源码范围内未发现剩余的具名测试用例。
- 项目依赖、锁文件、测试运行器及补丁、框架配置与通用辅助保留；旧用例登记清空，工程门禁入口改为目录发现。
- `bun run typecheck`、`bun run lint`、`bun run architecture:check --changed` 通过；Lint 为 0 告警／0 错误，架构为 0 违例。没有执行测试，也未新增测试。
- 未修改生产业务代码，未提交或推送。
