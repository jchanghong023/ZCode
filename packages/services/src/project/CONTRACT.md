# 当前后端项目服务

Current reachable boundary (2026-11-17): retain only `readTree` and `resolveSessionDirectories`. The connection binds the validated AIReq employee/client identity before either method runs. Remove directory browsing, project listing and session preparation RPCs, real filesystem/home reads and the old demo-project fixture.

AIReq `bootstrap` and `readWorkflow` own project roots, names, workspace identities and canonical published session references. MockRuntime owns native sessions and task rows. This service is a read-only projection, with no second project map, cache or mutable business owner. Projects use those business roots only; arbitrary runtime or caller paths must not expose host directories.

`readTree` serves current `@`/`#` session mentions. Enumerate existing listed native sessions from MockRuntime, not task mirrors: a normal `readWorkflow → subscribe → sendText` flow need not create a task row. Session existence, title and timestamps come only from the native session; a matching task mirror may supply only `pinned`/`archived`, otherwise both default to false. Access requires matching business/session workspace facts and either a canonical published reference or the exact employee/client draft creator. Missing native sessions and another actor's private sessions are excluded, never restored from task mirrors or treated as shared after a caught error. Published references may be read across actors; permission/read failures reject instead of falling back. Skill workspace identities reuse the existing `skillDesign.workspaceIdentity` operation and the native Skill scope suffix, not a backend-specific identity prefix. The projection never creates task mirrors or rewrites runtime/business facts. No native facts legitimately means an empty task collection.

`resolveSessionDirectories` verifies the requested task, workspace path and stable workspace identity against the same business/runtime facts, including private drafts before they become listed tasks. Caller-provided identity must match existing identity and is preserved, never replaced by a path-derived host hash. Missing/inaccessible targets and workspace mismatches reject. The service does not create directories, launch Agent, change cwd or claim database/project editing capabilities.
