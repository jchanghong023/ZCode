# 当前后端项目服务

Current reachable boundary: retain only `readTree` and `resolveSessionDirectories`. The connection binds the validated AIReq employee/client identity before either method runs. Remove directory browsing, project listing and session preparation RPCs, real filesystem/home reads and the old demo-project fixture.

AIReq `bootstrap` and `readWorkflow` own project roots, names, workspace identities and canonical published session references. MockRuntime owns native sessions and task rows. This service is a read-only projection, with no second project map, cache or mutable business owner. Projects use those business roots only; arbitrary runtime or caller paths must not expose host directories.

`readTree` serves current `@`/`#` session mentions. Enumerate existing listed native sessions from MockRuntime without reading task mirrors: a normal `readWorkflow → subscribe → sendText` flow need not create a task row. Session existence, title and timestamps come only from the native session. Access requires matching business/session workspace facts and either a canonical published reference or the exact employee/client draft creator. Published references may be read across actors; missing native sessions and another actor's private sessions are excluded. Permission and read failures reject rather than returning fallback results.

Web `readTree()` accepts no arguments and rejects requests that supply any, including a `hostId` filter. The response contains only `{ projects, tasks }`. Project entries expose `id` and `name`. Session entries expose only `taskId`, `title`, `workspacePath`, `workspaceIdentity`, `createdAt`, `updatedAt`, and `projectId`. Mentions group by `projectId` and use the current Agent type as a search keyword without a provider field in the response.

Web `resolveSessionDirectories` accepts one session reference with `taskId`, `workspacePath`, and optional `workspaceIdentity`. It rejects additional arguments and extra fields in the reference, including `hostId`, before lookup. It verifies the referenced task, workspace path and stable workspace identity against the same business/runtime facts, including private drafts before they become listed tasks. A supplied identity must match the registered identity. The response contains only `projectId`; file mentions validate the session before searching the current workspace only. Missing/inaccessible targets and workspace mismatches reject. The service does not create directories, launch Agent, change cwd or claim database/project editing capabilities.
