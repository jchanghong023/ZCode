# AIReq UI

公开入口为 `AIReqApplication` 与 `AIReqApplicationProps`。前端消费 `@zcode/services/aireq` 的业务契约，原生讨论复用 v4 会话。工作流持有文件、版本、确认和评审记录，前端持有选中范围、阅读位置和未发送输入。

## 导航与范围

`AIReqContext` 持有当前项目、Release、IR、Agent、页面及浏览器历史。SR 选择是 UI 私有状态，只定位文档；工作流读取和会话恢复按项目、IR 和 Agent 绑定同一会话。登录默认打开所有项目，项目内的近期 Release 按 IR 最新创建时间排列，选择版本原位查看概览，「进入需求共创」打开该版本的完整需求列表。设置往返、浏览器历史及切范围继续走同一离开门禁。关键字和列筛选按历史槽恢复，恢复时不沿用旧页码；项目或 Release 切换均从第一页开始。普通导航的 Release 在有效快照中消失时，由范围所有者切到该项目的「全部需求」，标题、侧栏和列表使用同一选择；项目消失时返回「所有项目」。显式对象分享仍按既有规则校验和报错。数据重读以请求代际识别迟到结果；重连重订事件并重新读取，保留有效的会话与材料选择。

## 需求共创

每行的「讨论需求」「讨论方案」分别打开对应 Agent 的会话，「查看文档」「复制软链接命令」为同组文档操作。所有人可进入需求 Agent 和打开文档；项目开发和测试可进入方案 Agent。项目工作目录准备好后即可复制项目级软链接命令。每个 IR 为两个 Agent 各绑定一个原生会话。打开 Agent 时，该 IR 最新文档在统一右侧工作区展开一次。用户收起后，文件或消息更新保持面板的开合。表格按钮在列表内打开文档。IR 的录入、删除及 Release 管理只在云龙进行，AIReq 无对应入口、表单草稿或业务命令。

云龙项目和 IR 字段来自页面绑定的快照，AIReq 本地项目配置、文档、版本、评审和会话按原归属保留。显式刷新成功后更新快照；刷新期间由业务通知触发的重读不得使旧快照覆盖成功刷新的投影。IR 详情评论的写入、回执和回读，以及其他对象级写入的界面反馈，都仅作用于发起操作的项目和 IR。

「同步全部项目到红区」不受项目、Release、筛选或分页影响。按钮在途状态和错误由当前登录页面持有，不随项目或 Release 切换重置。

聊天评审按钮调用 `reviewDocuments`。服务端使用接纳时最新已保存材料，不绑定工作流 revision 或定版预检快照，把独立子代理的结果写回原会话。界面依据公开记录展示运行、失败及旧内容提示。评审与版本确认可分别发起。

文档区默认显示最新版本，可浏览完整文件及已确认历史。开发或测试点击「检查定版条件」调用 `validateDocumentVersion`。右栏保留正文与目录，底部展示预检范围、文件清单和问题，允许定位文件与确认本次快照。显式提交把预检返回的 `snapshot` 原样交给 `confirmDocumentVersion`，不使用普通命令的工作流 CAS 判定。版本或文件漂移、他人已定版时 RPC 拒绝，不能改为确认新快照；用户可重新检查。快照一致但当前规则复核未通过时，从结果中与 `receipt` 同级的 `documentValidation` 读取问题。成功则固定全套文件、保留版本号并记录工号和时间。首次有效文件写入创建 V1，未确认时继续更新同一版，确认后首次改动创建下一版。材料的选中路径、版本和重读反馈属于各文档标签页。详见[需求共创](../../../../docs/specs/aireq/proposals.md)与[统一右侧工作区](../../../../docs/specs/aireq/unified-side-pane.md)。

## 其他入口

角色管理按项目显示开发和测试名单，所有用户可查看名单和操作按钮。只有管理员能添加或移除工号。项目地址和默认分支用于只读代码访问。AI 设置提供两个讨论 Agent 与两个评审子代理的模型及指令配置；设置修改走原编辑基线和离开门禁。

在线人员由服务端连接投影提供。主题使用既有 store；AIReq 每次打开或重新加载网页时默认使用钴蓝日间，动效主题仅在用户显式选择时启用。Sketch 复用原生聊天的附件端口。平台操作由 `IPlatformService` 提供。

公开服务及发布边界见[契约设计](../../../../docs/specs/aireq/contract-design.md)。
