# AIReq UI

公开入口为 `AIReqApplication` 与 `AIReqApplicationProps`。前端消费 `@zcode/services/aireq` 的业务契约，原生讨论复用 v4 会话。工作流持有文件、版本、确认和评审记录，前端持有选中范围、阅读位置和未发送输入。

## 导航与范围

`AIReqContext` 持有当前项目、Release、IR、Agent、页面及浏览器历史。登录默认打开所有项目，Release 卡片直接打开对应范围的需求共创。想法池跨项目。设置往返、浏览器历史及切范围继续走同一离开门禁。数据重读以请求代际识别迟到结果；重连重订事件并重新读取，保留会话和材料的当前选择。

## 需求共创

每行提供需求 Agent、方案 Agent 和查看文档。所有人可进入需求 Agent 和打开文档；项目开发和测试可进入方案 Agent。每个 Agent 有独立的原生会话。打开 Agent 时，该 IR 最新文档在统一右侧工作区展开一次。用户收起后，文件或消息更新保持面板的开合。表格按钮在列表内打开文档。页头提供「新建需求」，草稿由前端持有，通过 `createProposal` 为选定 Release 保存短需求，创建时不自动发消息。

聊天评审按钮调用 `reviewDocuments`。服务端读取发起时的最新材料并把独立子代理的结果写回原会话。界面依据公开记录展示运行、失败及旧内容提示。评审与版本确认可分别发起。

文档区默认显示最新版本，可浏览完整文件及已确认历史。开发或测试点击「确认版本」调用 `validateDocumentVersion`。检查失败的弹窗展示按路径分组的问题，检查通过的弹窗提供「确认定版」。显式提交发送 `confirmDocumentVersion`，服务端复核并固定全套文件，沿用版本号并记录工号和时间。首次有效文件写入创建 V1。文件在版本未确认时继续更新同一版；确认后首次改动创建下一版。材料的选中路径、版本和重读反馈属于各文档标签页。详见[需求共创](../../../../docs/specs/aireq/proposals.md)与[统一右侧工作区](../../../../docs/specs/aireq/unified-side-pane.md)。

## 其他入口

角色管理按项目显示开发和测试名单，所有用户可查看名单和操作按钮。只有管理员能添加或移除工号。项目地址和默认分支用于只读代码访问。AI 设置提供两个讨论 Agent 与两个评审子代理的模型及指令配置；设置修改走原编辑基线和离开门禁。

在线人员由服务端连接投影提供。主题使用既有 store；每次打开或刷新使用动效主题。Sketch 复用原生聊天的附件端口。平台操作由 `IPlatformService` 提供。

公开服务及发布边界见[契约设计](../../../../docs/specs/aireq/contract-design.md)。
