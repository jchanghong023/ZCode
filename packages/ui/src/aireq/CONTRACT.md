# AIReq UI

在线人员遵循 `docs/specs/aireq/section-navigation-and-ideas.md` 的全系统在线人员规则：服务端连接 owner 唯一持有工号／IP 引用计数，readPresence 读取带 revision 的快照，presence 事件推送相同投影；客户端只读并忽略旧版本，不新增认证、工作流或 v4 状态。

公开入口为 `AIReqApplication` 与 `AIReqApplicationProps`。前端只消费 `@zcode/services/aireq` 的正式数据源与现有原生 v4 会话，不保存第二份业务事实。

## 导航与范围

`AIReqContext` 唯一持有项目、具体 Release、对象选择、页面、提案任务与浏览器历史。提案入口为需求工作台，独立任务和审查详情通过同一 owner 导航；任务参数仅属于 UI 历史与对象 URL，不增加业务 owner 或服务端选择 DTO。全局页面为所有项目与想法池。所有项目是默认登录页，各 Release 卡片通过 `openProject` 进入对应版本的项目概览。项目概览与需求共创归版本工作区；项目和 Release 选择器仅在工作区显示，无全部版本选项。

概览从当前 Release 的提案与评审事实派生全体人员的待确认统计。

角色管理在页面内选择项目，所有用户可查看开发和测试名单，操作按钮始终显示。管理员可添加工号和确认删除，普通用户的按钮禁用。列表使用工作流投影，写入走通用版本命令。

导航、历史、项目／版本切换、设置往返和退出均消费唯一未保存门禁。Context 不建立项目读取缓存或平行范围。读取以代际拒绝迟到结果；业务事件只使投影重读，重连不自动重放写入。

项目概览的上下文返回来源仅由 Context 导航状态持有，并随同身份、会话的浏览器历史恢复；仅显式从概览打开目标时产生。侧栏直达、切项目／Release 清除来源，返回复用 select 与既有门禁。Shell 保留同范围概览挂载以保存筛选和滚动，不保存第二份业务投影；返回带使用既有顶部空间，和正文列对齐。具体规则及验收见分区导航规格。

## 工作区

需求共创读取当前项目与 Release 的全部需求。已归档 IR 沿统一入口打开只读详情，可查看原始需求、交付记录、材料及讨论评审历史。

想法池导入／导出单列原始需求 CSV；正式导入只发 `importIdeas`。转入选定版本经正式命令原子创建提案。需求共创的新增与批量导入立即创建提案，不自动运行 AI、拆 SR 或批准；业务 Markdown 只对应新 IR 的 requirements.md。

讨论复用原生会话。用户从需求澄清或方案设计提交当前材料版本后才启动对应评审。评审页读取材料校验与执行事实，只重试当前失败或缺报告的尝试；直接展示当前报告正文，随后提供业务确认或三方分别确认；意见不作门禁。需求确认固定项目、IR、评审 ID 与材料摘要，已失效时重新阅读后才能再次打开。第三个角色确认后，开发人员在交付弹窗核对完整清单并确认提交。成功后进入同一需求的归档详情，查阅只读材料与历史。

Context 在送审成功后从同一讨论打开对应汇总。三方从同一份方案综合报告完成确认。需求评审、方案审查和交付确认页提供「退回修改」。当前方案对话并列提供「提交方案审查」与「退回业务澄清」。退回弹窗持有当前对象、版本与意见草稿，通过 `returnProposal` 提交明确目标。成功后导航至同一 IR 的需求澄清或方案设计，意见由工作流投影展示。材料生命周期继续由 Agent 和工作流持有。

右侧统一多 Tab 由 `side-pane/AIReqSidePaneContext.tsx` 管理，材料与历史共享打开、激活、关闭、恢复、排序和完整视图控制；每个 Tab 保留自己的对象和 Release。Tab 注册离开门禁，不建立第二份业务 owner。具体契约见 `docs/specs/aireq/unified-side-pane.md`。

当前 `AIReqWorkbench` 在首选材料的内容摘要变化时会重置文件选择。材料重试请求仅携带目标和路径，当前材料的反馈也没有绑定内容版本。历史依赖图仍收到当前 IR 的方案轮次和 SR 清单。目标规则见[材料阅读规格](../../../../docs/specs/aireq/unified-side-pane.md#材料阅读)。

## 身份与展示

`zai-motion` 与既有主题共用 store 和广播路径。浏览器每次打开或刷新时，首屏与新建 store 均使用 `zai-motion`。切换只在当前页面内生效，主动选择优先于广播，重新连接保留当前 store。`AIReqMotion` 只负责本地装饰和一次性动画。减少动态效果或性能模式开启时停用主题动效与新增指针监听。行为见[默认动效主题](../../../../DESIGN.md#默认动效主题)。

Web 入口固定同一 clientId 供 AIReq identity、WebSocket、v4 握手和命令信封使用。全部合法工号可读取共享已发消息及附件，并执行满足对象、版本、幂等及阶段门禁的操作。原生 composer 按工号、客户端、工作区和会话隔离私有草稿、未发附件及输入历史。断线保留同工号的会话绑定，显式恢复仅重读原有会话，不重放命令。见[连接身份规格](../../../../docs/specs/aireq/connection-identity.md#2-工作区与会话)。

设置包含外观、项目配置、AI 配置和文档格式。AI 配置含模型和 Agent 指令，沿用编辑基线和草稿门禁。Sketch 支持画布及 PNG 附件。

Footer 业务桥复用通用 footer 的展示端口，仅提供当前工号、切换、帮助和主题等辅助工具；不挂载旧账户交易菜单，不消费后端来源元数据。页面共用居中内容列与主题 token。工具错误展示安全正文，不把错误码当用户文案。

业务规格见 `docs/specs/aireq/section-navigation-and-ideas.md`、`proposals.md` 与 `tools-settings.md`。公开服务边界见 `contract-design.md`；部署限制见 `docs/architecture/mock-backend.md`。
