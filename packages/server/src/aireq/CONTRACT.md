# AIReq 模拟服务端契约

## 业务事实与原生运行时

项目与 IR 业务字段来自云龙，Release 由当前目录中 IR 的 PI 归组，IR 可以不属于任何 Release。AIReq 不创建项目、Release 或需求，也不删除需求；IR 从云龙目录消失时保留本地工作流记录。工作流持有项目角色、当前材料、已确认快照和文档评审记录；首次载入 IR 时绑定独立的需求和方案会话。所有有效工号可以读取文档和进入需求会话。项目的开发或测试可进入方案会话、读取方案评审及确认版本。管理员沿用全项目角色。角色校验适用于业务命令、原生会话读取与再次执行、目录和附件访问。

纯对话无文件变化时保留原版本。尚无材料的 IR 没有文档版本，首次写入文件生成 V1。未确认的同版可反复修改。`validateDocumentVersion` 只读检查完整性及格式并返回 `snapshot`。确认先核对提交的快照仍匹配未定版的版本及全部文件，再按当前规则复核，成功则固定文件、SR、确认人工号和时间。文件漂移、版本变更或已定版时 RPC 拒绝；快照匹配但复核未通过时结果含失败的 `receipt` 与同级 `documentValidation`，报告问题路径和原因。版本号在确认时保持不变，确认后的首次文件变化把固定快照移入历史并开启下一版。删除文件不重置版本计数或删除已确认历史。

`projects.saveRepository` 只更新当前页快照中已登记且仍有效的云龙项目。请求必填 `projectId`、`repositoryUrl`、`defaultBranch`、`workDirectory`、`expectedRevision`、`operationId`，不接受 `name`。配置保存保留项目级 CAS 与按连接身份、操作编号的幂等裁决。仓库地址与默认分支仅配置只读代码入口。设置提交前准备服务端共享文档目录并检查材料基线；工作流在提交材料变更前发布该 IR 的完整最新版，确认快照独立保留。详见[项目工作目录](../../../../docs/specs/aireq/contract-design.md#项目工作目录)。

原生会话、附件、队列、订阅及水位归 `MockRuntime/MockZCodeAgentService`。工作流提交业务事实后发出更新通知。已接纳输入保留原工号、连接 ID 和正文，执行按会话绑定的模型、指令及实际输入路由，提交材料前重验操作权限。两个 Agent 写入各自的材料，继续在同一会话讨论。模型配置和追加指令共享四个角色。模拟对话和评审处理内存中的材料，业务材料另可发布到已配置的共享文档目录。

## 按需评审

`reviewDocuments` 在工作流接纳时记录最新文件快照、版本、请求工号、时间及独立评审角色配置。固定提示词经原生队列在发起评审的会话中调度，只读子代理把报告返回相同会话，同时结算工作流评审记录。停止或失败可重新发起评审；评审不会写文件、确认版本或阻塞确认。当前文件清单变化使对应旧快照的报告标为旧内容，即使版本号相同。

模拟运行时使用原生工具和子代理行显示内存检查结果。评审快照和模型绑定在接纳时捕获，排队时不会被后续聊天、修改或配置变化覆盖。其他输入保留其投递身份，评审运行期间的聊天随后处理。原型评审不调用真实模型或仓库，不直接读取业务文件系统；正式运行时需由真实子代理执行相同的只读任务。

## 调用与回执

公开 `MockAIReqService` 由 `@zcode/services/aireq` 的接口与 descriptor 注册，bootstrap 契约版本为 `38`。普通调用绑定合法工号和 clientId，原生命令还要求原有 v4 握手及 HTTP 固定连接身份一致。业务写操作使用各自的校验与签名。普通 `command` 以第三参工作流 revision 做 CAS；`confirmDocumentVersion` 用预检快照而非该修订号，`reviewDocuments` 直接捕获接纳时最新已保存材料。命令按实际连接身份及 operationId 去重；同 ID 同内容显式重试返回原结果，复用 ID 但改内容则拒绝。进程重启不保留回执；重连只恢复订阅和重读。

服务端为每条连接绑定云龙目录快照；可选的 WebSocket `pageId` 与工号、clientId 一起支持在最后一个连接断开后 30 分钟内恢复快照。普通读取复用该页已绑定目录，叠加当前本地状态。首次读取允许部分项目失败；刷新仅在完整目录成功后替换快照，普通读取在此之前仍取旧目录。`readWorkflow`、`retrySession` 使用同源的页面目录和当前本地工作流，按项目、IR 和 Agent 定位会话；恢复不得绕过该页目录。命令目标只接受项目和 IR；这些目标均不接受 SR。`readRequirementDetails` 按项目组和 IR 业务号读取页面快照中的云龙字段。项目目录允许包含多个需求域，`requirementComments.*` 按页面快照内的项目、该条 IR 的需求域和业务号调用云龙。

手动 `proposals.syncToRedZone` 只接收 `[]`，接纳时固定该页已加载的云龙目录，无目录则拒绝；提交给传输端口时读取当前需求材料。自动同步每 5 分钟读取目录，不改页面快照。交接只含云龙来源的项目及 IR 业务字段（包括未截断的原始描述）和可选的当前 `requirements.md` 完整正文；不完整目录或不可读的现有材料使整次同步失败。接收端分开存储导入副本和红区自有文件，不以缺失正文删除文件。

列配置按连接工号在服务工作目录持久化，迁移写入只在记录缺失时生效。材料读取恢复绑定项目、Release、IR、路径和正文摘要。

在线人员由连接 owner 持有工号及 IP 引用计数。Release 统计从同一工作流按项目聚合。

工作流不把幂等记录当作操作历史下发。

配置读取经 bootstrap。模型和追加指令各自使用独立 revision；配置成功后服务端记录操作、实际操作者和时间，避免把配置正文记录进日志。隐藏 Skill 仍在已有原生会话和私有存储中工作。Skill 保存和读取共享唯一内存文件事实。

v4 请求及发出的帧使用现行严格 schema，会话操作继续由原生 runtime 对工作区、订阅及附件行校验。执行失败保留已接纳输入，在原生历史及投影返回相同的安全失败信息。
